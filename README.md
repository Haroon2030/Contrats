# نظام إدارة العقود — أسواق الرشيد

المشروع الآن على مرحلتين متوازيتين:

| المكوّن | المسار | التقنية |
|---|---|---|
| الواجهة الأمامية | `frontend/` | Next.js 15 + React 19 (App Router)، عربي RTL |
| الواجهة الخلفية | `backend/` | NestJS 11 + TypeORM |

النظام القديم (Django) أُزيل من هذا المشروع. يبقى `db.sqlite3` و`media/` للتطوير المحلي، لأن الواجهة الخلفية تقرأ منهما.

الواجهة الجديدة تتصل بنفس قاعدة البيانات وبنفس الجداول وبنفس حسابات المستخدمين وبنفس مجلد المرفقات الذي كان يستخدمه النظام القديم.

## التشغيل المحلي

المتطلبات: Node.js 22 أو أحدث.

**1) الواجهة الخلفية (NestJS) على المنفذ 4000**

```bash
cd backend
cp .env.example .env
npm install
npm run build
npm start
```

الإعداد الافتراضي في `.env.example` يستخدم ملف `db.sqlite3` الموجود في جذر المشروع (نفس بيانات التطوير الحالية).

**2) الواجهة الأمامية (Next.js) على المنفذ 3000**

```bash
cd frontend
npm install
npm run build
BACKEND_URL=http://localhost:4000 npm start
```

ثم افتح: http://localhost:3000/login

> في وضع التطوير يمكن استخدام `npm run dev` (الواجهة) و`npm run start:dev` (الخادم) بدل البناء.

## متغيرات البيئة (الواجهة الخلفية)

| المتغير | المعنى |
|---|---|
| `DB_DRIVER` | `sqlite` للتطوير المحلي، أو `mysql` للإنتاج |
| `DB_SQLITE_PATH` | مسار ملف SQLite (افتراضي `../db.sqlite3`) |
| `MYSQL_HOST`, `MYSQL_PORT`, `MYSQL_DATABASE`, `MYSQL_USER`, `MYSQL_PASSWORD` | نفس متغيرات Django تماماً |
| `MEDIA_ROOT` | مجلد الميديا في Django (افتراضي `../media`) |
| `JWT_SECRET` | سر توقيع رمز الجلسة. **إلزامي في الإنتاج** |
| `JWT_EXPIRES_SECONDS` | مدة الجلسة بالثواني (افتراضي 8 ساعات) |
| `PORT` | منفذ الخادم (افتراضي 4000) |
| `CORS_ORIGIN` | عناوين الواجهة المسموح لها (إن لزم) |
| `COOKIE_SECURE` | `1` عند العمل عبر HTTPS |

## الاتصال بالإنتاج: ما الذي حافظنا عليه

- **قاعدة البيانات:** الكيانات في `backend/src/database/entities.ts` تطابق جداول Django (`contracts_contract`، `contracts_vendor`، `auth_user`، …) عموداً بعمود. `synchronize` معطّل، فلا يُنشئ الكود ولا يعدّل أي جدول.
- **كلمات المرور:** الحسابات الحالية تعمل بدون إعادة تعيين، لأن التحقق يقبل صيغة Django `pbkdf2_sha256` نفسها. وأي حساب ينشئه النظام الجديد يُحفظ بنفس الصيغة، فيعمل في النظامين.
- **أرقام العقود:** بصيغة `رقم المورد-تسلسل` كما في Django. التسلسل يأخذ أعلى رقم موجود + 1، فيتطابق مع Django ولا يتعارض مع أرقام غير متصلة.
- **المرفقات:** تُحفظ في `media/contracts/YYYY/MM/` بنفس التخطيط، فتبقى الملفات القديمة والجديدة قابلة للتنزيل من النظامين.
- **التوقيت:** تُكتب التواريخ بتوقيت UTC كما يفعل Django (`USE_TZ=True`)، ويُعرض التوقيت بالرياض.
- **سجل التدقيق:** كل إجراء يُكتب في `contracts_auditlog` بنفس الحقول والقيم (`action`, `from_status`, `to_status`, `details`).

**ما الذي لا يتشارك بين النظامين:** جلسة الدخول. Django يستخدم كوكي جلسته، والنظام الجديد يستخدم رمز JWT مستقلاً. المستخدم يسجّل الدخول مرة أخرى في النظام الجديد.

## ما الذي يعمل الآن

- تسجيل الدخول (قفل بعد 5 محاولات فاشلة لمدة 15 دقيقة)
- لوحة التحكم: ما ينتظر إجراءك، الحالات، القرب من الانتهاء، الخصم التقديري حسب القسم، توزيع الأنواع
- سجل العقود: بحث وفلاتر (الحالة، النوع، القسم، الانتهاء، بانتظار إجرائي) وتصدير CSV
- صفحة العقد: مراحل، تبويبات (ملخص، شروط، مرفقات، ملاحق وتاريخ، سجل التدقيق)، إجراءات حسب الدور والمرحلة مع نوافذ تطلب السبب
- إنشاء المسودة وتعديلها وحذفها، والإرسال مباشرة للاعتماد
- مسار العمل كاملاً: إرسال ← مراجعة قانونية ← اعتماد ← توقيع ← تفعيل تلقائي عند تاريخ البدء، مع الرفض والإعادة للمسودة والتصعيد والإلغاء
- المرفقات: رفع وتنزيل
- الأهداف والخصومات (من شرائح العقود)
- المستخدمون (مدير النظام): إنشاء وتعديل وتعطيل
- القوائم المرجعية: الأقسام والموردون وأنواع الأرفف (إضافة وتعطيل، بلا حذف)
- سجل التدقيق مع فلاتر بالعقد والتاريخ
- التنبيهات: تُحسب دورياً (كل 5 دقائق عند القراءة، أو يدوياً عبر `POST /api/alerts/refresh`) وتظهر في الجرس

## ما الذي لم يُنفّذ بعد، ولماذا

هذه البنود تحتاج جداول أو أعمدة جديدة في قاعدة الإنتاج. أضافتها تغيّر قاعدة بيانات Django، لذلك لم أضفها دون موافقة:

1. **أنواع متعددة في عقد واحد:** الجدول الحالي يحمل نوعاً واحداً لكل عقد.
2. **أسطر الإيجار الشهرية، الفعاليات التسويقية، الفروع والأرفف التشغيلية:** تحتاج جداول جديدة. الشاشة «التشغيل» معروضة كمؤجلة.
3. **القوالب والشروط (بنود بإصدارات، وقالب PDF):** تحتاج جداول جديدة. الشاشة «القوالب والشروط» معروضة كمؤجلة.
4. **التغيير الإجباري لكلمة المرور عند أول دخول:** يحتاج علامة على المستخدم في قاعدة البيانات.
5. **التحقق من 5 مستندات لعقد فتح الحساب:** يحتاج نوعاً مستقلاً للمستندات.
6. **صافي المشتريات الفعلي لحالة الشرائح (متحقق / غير متحقق):** لا يوجد مصدر مشتريات في قاعدة البيانات. تظهر الحالة «لا توجد بيانات».
7. **تصدير Excel حقيقي (xlsx):** الحالي CSV يفتحه Excel مباشرة. xlsx يحتاج مكتبة إضافية.
8. **رقم جوال الممثل (يبدأ بـ 05):** غير موجود في جدول الموردين الحالي.
9. **التصعيد الآلي بعد مدة الانتظار:** لم يُنفّذ. التصعيد اليدوي يعمل.

## ملاحظات تشغيلية

- **حذف المسودة:** يحذف سجلها أيضاً، كما يفعل Django. إن أردت الاحتفاظ بالسجل، أحوّله إلى إلغاء.
- **قفل الدخول:** في الذاكرة، يُصفّر عند إعادة تشغيل الخادم. مقبول لخادم واحد، ويحتاج تخزيناً مشتركاً إن شُغّل أكثر من نسخة.
- **بناء الواجهة الأمامية:** مسار `/api` يُعاد توجيهه إلى NestJS. هذا التوجيه يُحسب وقت البناء، لذلك مرّر `BACKEND_URL` وقت `npm run build` أو كـ build arg في Docker.

## النشر على Dokploy

الملف `docker-compose.yml` في الجذر يعرّف خدمتين: `contracts-api` (من `backend/`) و`contracts-web` (من `frontend/`).

**الخطوات في Dokploy:**

1. أنشئ volume باسم `contracts-media` (أو غيّر المتغير `MEDIA_VOLUME`). **يجب أن يكون نفس volume مرفقات النظام القديم** حتى تبقى المرفقات القديمة قابلة للوصول. اعرف اسمه من إعدادات التطبيق القديم في Dokploy ثم اضبط `MEDIA_VOLUME` بذلك الاسم.
2. أنشئ تطبيقاً من نوع **Compose** وصدّر مستودع المشروع، واختر الملف `docker-compose.yml`.
3. في تبويب Environment أضف:
   - `MYSQL_HOST`, `MYSQL_PORT`, `MYSQL_DATABASE`, `MYSQL_USER`, `MYSQL_PASSWORD`: نفس قيم Django.
   - `JWT_SECRET`: سلسلة عشوائية طويلة (لا تُعاد استخدامها).
   - `COOKIE_SECURE=1` إذا كان النطاق HTTPS.
4. في تبويب Domains اربط نطاقاً أو عنواناً بالخدمة `contracts-web` على المنفذ `3000`. الخدمة `contracts-api` داخلية فقط.
5. اضغط Deploy.

الواجهة تستدعي `/api` على نفس النطاق، وNext يوجّهها إلى `contracts-api` داخل الشبكة. لذلك لا تحتاج أن تفتح الـ API للعالم.

**قبل النشر، تحقق من:** أن `backend/Dockerfile` و`frontend/Dockerfile` يبنيان في بيئة Docker الحقيقية. لم أتمكن من تشغيل Docker هنا، ونجح البناء محلياً عبر `npm run build` فقط.
